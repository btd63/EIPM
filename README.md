# ADRF Benchmark Code

This directory contains the code used to generate simulation datasets, train the EIPM model, and evaluate ADRF estimation on both simulation data and the NMES real-data benchmark.

## Layout

- `run/`: executable entry scripts
- `lib/`: import-only Python modules
- `data/`: public input data and generated `.npz` datasets
- `out/`: trained checkpoints and result CSV files
- `기타/`: archived or non-core materials not needed for the main public workflow

## Main Scripts

- `run/data_sim.sh`: generates the full simulation sweep datasets and writes them into `data/`
- `run/train.sh`: trains all EIPM models needed for both simulation and NMES
- `run/eval.sh`: evaluates all enabled methods and writes `results_*.csv` files into `out/`

The shell scripts try to activate the conda environment `ten` if `/usr/local/miniconda3/etc/profile.d/conda.sh` exists. If that path does not exist on your machine, the scripts simply use the current `python` on your `PATH`.

## Inputs

### 1. Simulation

Simulation datasets are generated by `run/data_sim.sh`. They are saved in `data/` as `.npz` files, one file per configuration.

The built-in simulation sweep covers:

- scenarios: `linear`, `nonlinear`
- `n_train`: `250, 500, 1000, 2000`
- `(d_X, |S_T|, |S_Y|)`: `(5,5,5)`, `(50,5,5)`, `(50,5,50)`, `(50,50,5)`, `(50,50,50)`
- `pi_0`: `0.0, 0.2, 0.5, 0.8`

Default baseline settings are:

- `n_eval = 1000`
- `n_rpt = 100`
- `seed = 42`
- `beta_T_scale = 0.2`
- `beta_T0_scale = 0.2`

### 2. NMES

The public NMES input file is expected at:

- `data/nmes_data.csv`

The current code expects at least these two columns:

- `packyears` as treatment
- `TOTALEXP` as outcome

All remaining columns are treated as covariates, with categorical variables one-hot encoded internally.

## Reproducible Workflow

Run all commands from this directory:

```bash
cd code
```

### Step 1. Generate simulation datasets

```bash
run/data_sim.sh
```

This writes the simulation sweep datasets to `data/`.

### Step 2. Train EIPM

```bash
run/train.sh
```

This script does two things in sequence:

1. It reads the previously generated simulation `.npz` files from `data/` and trains EIPM checkpoints for all simulation settings. These are written under:

- `out/models/eipm_sweeps/`

2. It reads `data/nmes_data.csv`, constructs the NMES adapter dataset internally, and trains the corresponding EIPM checkpoints. These are written under:

- `out/models/eipm_nmes/`

The NMES adapter dataset itself is also saved into `data/` as:

- `nmes_tmp_for_eipm_*.npz`

### Step 3. Evaluate ADRF estimation

```bash
run/eval.sh
```

This script evaluates:

- the simulation sweep
- the NMES benchmark

and writes one CSV per method into `out/`.

Typical outputs are:

- `out/results_eipm.csv`
- `out/results_stabilized_gps.csv`
- `out/results_independence_weights.csv`

If you explicitly include `unweighted` in `--methods`, the script also writes:

- `out/results_unweighted.csv`

Each results file contains rows for:

- simulation sweep type: `n`, `dims`, `pi0`
- NMES: `sweep_type = nmes`
- smoothing: `NW`, `LL`

## Methods Included by Default

The default public evaluation path runs:

- `eipm`
- `stabilized_gps`
- `independence_weights`

`EIPM` is model-free in this code path: it directly learns `log w_theta(x,t)` and uses checkpoint model outputs at evaluation time. It does not estimate or use a propensity/GPS model.

## About CBGPS

Exact `CBGPS` is not enabled by default in the public workflow. In this repository, exact CBGPS requires an external R-based bridge or precomputed weights. If you do not provide that external component, the safe public replication path is to use the default methods above.

If you already have external weights, `run/eval.sh` supports an additional `--external_weights_dir` argument.

## Useful Overrides

All three scripts accept optional arguments. Common examples:

```bash
run/data_sim.sh --n_rpt 3 --n_eval 1000
run/train.sh --device cuda:0 --max_steps 300 --n_rpt 3
run/eval.sh --n_rpt 3 --methods eipm,stabilized_gps,independence_weights
```

For faster NMES runs:

```bash
run/train.sh --nmes_sample_n 2000 --nmes_n_rpt 5
run/eval.sh --nmes_sample_n 2000 --nmes_n_rpt 5
```

## Where to Look for Final Outputs

After the full pipeline finishes, the main outputs are:

- simulation and NMES result CSVs in `out/`
- trained EIPM checkpoints in `out/models/`
- generated simulation and NMES adapter datasets in `data/`

In other words, a researcher who wants to reproduce the public results should run, in order:

```bash
run/data_sim.sh
run/train.sh
run/eval.sh
```

and then inspect the `out/results_*.csv` files.
